# Актер Гэлакси

Одностраничный сайт для инвесторов: апартаменты в сданном комплексе «Актер Гэлакси» в Сочи (Курортный проспект, 105) как доходный актив.

Перенос дизайн-макета («Лендинг для инвесторов», `Main.dc.html`) на Next.js, тем же стеком, что сайты Mercato, «Поляна Пик», «Важные решения». Макет сверстан на классах, поэтому его стили перенесены в `globals.css` с теми же именами классов, а разметка разложена по компонентам секций.

## Стек

- Next.js 16 (App Router, standalone-сборка)
- React 19, TypeScript
- Docker

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
```

Прод:

```bash
npm run build
node .next/standalone/server.js
```

Docker:

```bash
cp .env.example .env
docker compose up --build
```

## Переменные окружения

Смотрите `.env.example`.

| Переменная | Когда читается | Назначение |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | сборка | канонический адрес сайта: метаданные, микроразметка, `robots.txt`, `sitemap.xml` |
| `YANDEX_VERIFICATION` | сборка | код подтверждения прав в Яндекс.Вебмастере |
| `GOOGLE_SITE_VERIFICATION` | сборка | то же для Google Search Console |
| `NEXT_PUBLIC_YM_ID` | сборка | номер счётчика Яндекс.Метрики; пусто - счётчик не подключается |
| `TELEGRAM_BOT_TOKEN` | запуск | токен бота для доставки заявок; без него заявка только пишется в журнал |
| `TELEGRAM_CHAT_ID` | запуск | чат или группа, куда бот шлёт заявки |
| `TELEGRAM_THREAD_ID` | запуск | тема супергруппы-форума; пусто - бот пишет в общую ленту |
| `TRUST_PROXY` | запуск | `1`, только если перед приложением стоит доверенный прокси |
| `LEADS_DATA_DIR` | запуск | каталог с журналом заявок, в докере том `leads-data` |
| `WEB_PORT` | запуск | порт хоста в docker compose, по умолчанию 3000 |

Переменные с пометкой «сборка» Next подставляет в код при `npm run build`, на запущенном контейнере их не поменять. В `docker-compose.yml` они уходят в `build.args`, так что смена домена, кода вебмастера или счётчика - это `docker compose up --build`.

**Домена пока нет.** Без `NEXT_PUBLIC_SITE_URL` канонический адрес, карта сайта и микроразметка указывают на `http://localhost:3000`. Кириллический домен можно писать как есть: он приводится к punycode через `new URL().origin`.

## Превью на GitHub Pages

```bash
npm run pages
```

Скрипт `scripts/gh-pages.sh` собирает статическую версию во временной копии проекта и пушит её в ветку `gh-pages`. Адрес: `https://<владелец>.github.io/<репозиторий>/`, владелец берётся из `origin`; если репозиторий переехал, его можно задать явно: `PAGES_OWNER=efimov-work npm run pages`. Рабочее дерево и `.next` не трогаются.

Отличия от прод-сборки:

- `output: 'export'` и `basePath` из имени репозитория (`STATIC_EXPORT=1`, `NEXT_PUBLIC_BASE_PATH`); пути к картинкам идут через `asset()` из `src/lib/asset.ts`;
- приёма заявок нет: на Pages нет сервера, форма покажет ошибку отправки;
- `SITE_NOINDEX=1`: `noindex, nofollow` в мета-тегах и `Disallow: /` в `robots.txt`, чтобы превью не попало в выдачу дублем будущего домена;
- счётчик Метрики и коды вебмастеров отключены.

В настройках репозитория (Settings → Pages) источник должен быть `Deploy from a branch`, ветка `gh-pages`, папка `/`. Для приватного репозитория Pages работает только на платном тарифе владельца.

## SEO

Тексты метаданных и сборка микроразметки лежат в `src/lib/seo.ts`. Адрес, координаты, телефон, фотографии и удобства берутся из `src/lib/content.ts`, из тех же констант, что рисуют страницу.

Выдаётся:

- `title`, `description`, `canonical`, `keywords`;
- Open Graph и Twitter Card с превью 1200x630, снятым с первого экрана;
- `robots.txt`: `/api/` закрыт, `Sitemap:`, отдельный блок для Яндекса с `Clean-param` (utm-метки, `yclid`, `gclid` и другие, список в `CLEAN_PARAMS`);
- `sitemap.xml` со всеми фотографиями страницы, `lastmod` по дате сборки;
- микроразметка одним `@graph`: `WebSite`, `WebPage` и `ApartmentComplex` с адресом, координатами (`geo`), ссылкой на карту, логотипом, фотографиями с подписями и списком удобств; телефон и `ContactPoint` добавятся, когда телефон появится в `content.ts`;
- иконки и `manifest.webmanifest`;
- `max-image-preview:large` для Googlebot;
- мета-теги подтверждения прав, если заданы `YANDEX_VERIFICATION` и `GOOGLE_SITE_VERIFICATION`;
- редирект 301 с `www.` на основной домен;
- Яндекс.Метрика, если задан `NEXT_PUBLIC_YM_ID`. Цели: `lead` - заявка отправлена, `phone` - нажатие на телефон. Цели с такими идентификаторами нужно завести в интерфейсе Метрики (тип «JavaScript-событие»).

Разметка: один `h1`, заголовки секций `h2`, карточки `h3`, цифры и характеристики списками `dl`, адрес в `<address>`. Фото первого экрана - `<img>` с `fetchpriority="high"`, а не CSS-фон, как в макете: так оно попадает в поиск по картинкам и быстрее отрисовывается. Все фотографии с описательным `alt`, планировки все в HTML, неактивные скрыты. Текст отдаётся с сервера, без JavaScript страница видна целиком: анимации появления включаются только после гидрации и только для блоков ниже экрана.

Шрифты Prata и Onest раздаются с того же домена через `next/font`, без запроса к Google Fonts.

## Заявки

Форма в конце страницы: имя, телефон, бюджет, цель покупки. «Получить расчет по лоту» в калькуляторе и «Запросить цену» в планировках ведут к ней и прикладывают к заявке параметры расчёта или выбранную планировку.

Российский номер набирается по маске `+7 (___) ___-__-__` и должен быть полным; номер с другим кодом страны вводится без маски, 10-15 цифр. Скрытое поле-ловушка отсекает ботов.

Заявка дописывается в `LEADS_DATA_DIR/leads.jsonl` до попытки отправки в Telegram, недоставленные дублируются в `leads-undelivered.jsonl`, в логе сервера строка `lead not delivered to telegram`. Частота ограничена по номеру (3 в час), по источнику (10 в час, только при `TRUST_PROXY=1`) и глобально (120 в минуту).

### Telegram

1. У `@BotFather`: `/newbot`, токен в `TELEGRAM_BOT_TOKEN`.
2. Добавить бота в рабочую группу и написать там любое сообщение.
3. `npm run tg chats` - напечатает готовую строку `TELEGRAM_CHAT_ID=...`, для групп с темами ещё и `TELEGRAM_THREAD_ID=...`.
4. `npm run tg test` - в группу придёт пробная заявка.

## Отличия от макета

- Переключатели шрифтовой пары, акцентного цвета и анимаций из редактора макета не перенесены, оставлены значения по умолчанию: Prata и Onest, `#C2A06A`, анимации включены.
- Большое фото в блоке «Архитектура» в макете не появлялось никогда: шторка `clip-path: inset(0 0 100% 0)` давала нулевую площадь, и IntersectionObserver его не видел. Здесь шторка ждёт появления родительского блока.
- Названия пунктов инфраструктуры крупные, как задано в стилях макета (`24px`). В превью макета они выглядели мелкими из-за служебной обёртки редактора, на которую попадало правило `.inf span`.
- Полосы расстояний в «Локации» без JavaScript видны заполненными; в макете без скрипта они оставались пустыми.
- `overflow-x: clip` вместо `hidden` на корне страницы: иначе не работает липкий блок результата в калькуляторе.
- Телефон и почта в блоке заявки скрыты, пока не заданы в `content.ts` (в макете заглушки `[ТЕЛЕФОН]`, `[EMAIL]`). Стоимость в планировках «по запросу» вместо заглушки `[ЦЕНА]`.
- Форма заявки настоящая: проверка телефона, состояния отправки и ошибки.
- Неиспользуемое из макета не перенесено: SVG-башня и схема побережья, для которых в разметке не было элементов.
